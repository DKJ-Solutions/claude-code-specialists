### Shipping a branch no longer re-runs the gates it already passed

Open a pull request in one step and ship it in a later one, and the lint and test gates used to run a
second time on a commit nothing had touched. They now run once. `open-pr.ps1` records what each gate
proved and against which exact working state, and `ship-pr.ps1` skips a gate only while that state is
unchanged.

**What you will notice:** the merge step stops spending minutes re-proving a green commit. Measured
across 293 merged pull requests here, the excess was **249 seconds on 28.3% of merges** -- and it lands
hardest on exactly the workflow where a branch is opened and shipped in separate steps.

**What you should stop doing:** reaching for `-SkipLint -SkipTests` because "it passed a minute ago".
That was the workaround, and the workaround was the defect -- it is correct only while the commit is
unchanged, and nothing checked which. The unchanged case now provably does not need the flags.

**The evidence is the content, not the clock.** A passing gate is recorded against a fingerprint of
what it actually judged: `HEAD` plus the content hash of every dirty and untracked file. Every failure
path -- no record, a malformed record, no git, a clock that moved backwards -- runs the gate rather
than skipping it, because a false refusal costs one gate run and a false skip costs an ungated merge.
The record lives in your git directory, so it is never committed and never shared between worktrees.

**Your CI is untouched.** A fresh checkout has no record, so a CI gate always runs for real.

### You can read your release notes as a web page instead of as markdown in a code host

The hand-written release note is the one document written for somebody outside the development work,
and until now reading it meant finding a directory, picking a version out of a filename, and reading
raw markdown. `build-release-notes-page.ps1` builds every note into one page -- a picker per release,
prev/next, keyboard arrows, a deep link per version, light and dark -- and with `-Worker` into a
Cloudflare Worker that serves it at `/notes/<32 hex>`.

**To get it:** the [`release-notes-page`](../../../../plugins/workflows/workflow-davekjohn/skills/release-notes-page/SKILL.md)
skill is its page. Two optional seams name the page title and the worker; answer neither and you still
get a page, and simply host it nowhere.

**It publishes nothing.** `npx wrangler deploy` stays a deliberate, separate step. If you do deploy,
verify a redeploy against **the bytes the URL serves**, never against the deploy command's own output:
once wrangler has deployed a worker, an API-side upload only creates inactive versions, silently, while
the live page stays the old one.

**Decide where the path token lives before you generate one.** Private repo: commit it, so a tracked
token survives a lost machine. Public repo: keep it out, and accept that nothing in git then remembers
the URL. The token is an input and is never invented for you -- a regenerated token means every link
you have already sent returns 404 while the build and the deploy both report success.

### Your session start gets shorter when a repo is behind on several plugins

One consumer behind on four plugins printed the same sentence four times. The lines now fold per
consumer: on the real signal set here, four lines of 733 characters became one of 311 -- a **58%** cut,
paid back on every compaction as well as every session start.

**Nothing is lost.** Every plugin name still appears, moved beside its consumer, so "which plugins, in
which repo" is still answerable. The fold is conservative by construction -- marker, consumer *and*
message must match -- so two different problems can never read as one.

### Your specialists in the Shopify, e-commerce and life-hub teams stop working from a hand-typed rule

The rule telling a specialist it does not receive the conversation history existed in one canonical
source and eleven hand-typed copies, already drifting into **three different wordings**. Coverage is
now 26 of 26 agent definitions, all from the one source, with no hand-typed variant left.

**Where it shows:** `team-shopify`, `team-ecomm` and `team-lifehub` carried none of the canonical block
before this release. If you enable any of them, nine of those eleven definitions were live in your
repo.

### A finding gets measured before somebody scopes a repair from it

Your Chief of Staff already checked three things about an incoming report -- its symptom, its reason,
and the repair it proposes. There is now a fourth: **its size**.

**Why this one is different:** a report is usually right about *what* is wrong and still wrong about
*how much*, because the count it carries is whatever the reporter's search matched. Scope to that and
either the repair leaves most of the problem standing while looking finished, or it runs a mechanical
fix across a subject far larger than anyone meant.

**What you will see:** the subject measured in its own terms before the work is scoped, and a large
disagreement filed back to you as a finding rather than quietly absorbed -- because the decision to
widen a job belongs to whoever owns it.

### Smaller fixes you may notice

- **Two lint checks stop missing indented code fences.** Checks 15 and 16 matched fences anchored at
  column 0 rather than calling the shared function that allows indentation, so an indented fence was
  invisible to both. Nothing misfires today; the day a measured figure appears inside one, it would
  have been judged as prose.
- **Your governance document has a method for getting smaller.** Nothing here edits your `CLAUDE.md`.
  What travels is the approach, demonstrated on this repo's own: separate the decision from the
  evidence for it, measure the block before cutting it, and move the prose verbatim. This repo's went
  from 36,967 B to 28,298 B -- **23% smaller** -- by moving one sub-item of one list.
- **Four documents that described something the tree does not do were corrected**, including a security
  policy that told researchers there was no hosted service when there is one, now named in scope with
  its token as the stated boundary.

## What it is worth

**The largest repeated cost in the release procedure is gone, and it was measured before it was
built.** The merge re-running gates the pull request had already proved was named in *what was still
open* for five consecutive releases without being acted on. It is closed here. The figure in
circulation for it was also wrong -- the earlier notes reported "about three minutes" as the whole
merge leg, conflating it with the gate re-run inside it. The real number is 249 seconds on 28.3% of
merges, established from 293 pull requests, with the one confound that could have faked it ruled out.
That is the difference between acting on a feeling and acting on a measurement.

**A workaround that was quietly carrying risk has been removed rather than made more comfortable.**
Every one of the nine pull requests shipped on August 15 used `-SkipLint -SkipTests` deliberately,
because the identical commit had passed both gates minutes earlier. That reasoning is correct exactly
while the commit is unchanged and dangerous the moment it is not, and nothing checked which. The
choice was to make the unchanged case provably safe, not to make the flag easier to reach.

**The most dangerous script here now has real coverage.** `cut-release.ps1` bumps every plugin version,
empties the changelog, commits directly on the trunk and tags -- under the narrow exception that puts
no pull request and no CI between a defect and the tag. Its only dedicated coverage was a drift guard
and asserts on its own source text. It is now driven end to end against a throwaway repository, and the
fixture found a real bug in its first draft: a slightly malformed history table made the cut write no
row and refuse no major, silently. That is precisely the shape a script running unattended on the trunk
produces when its input is a little off, and nothing here could see it before.

**Reading a release note stops requiring a developer.** The one document written for people outside the
development work no longer has to be read as raw markdown in a code host. That is the whole point of
writing it separately, and until now the last step of the delivery was missing.

**Three of twenty-two findings in one review were mis-measured, by the team that filed them.** All
three were caught only because the repair began with a recount, and each would have produced a
confidently wrong fix: one leaving 310 of 342 cases standing, one feeding 17 role-specific sentences to
a generator for deletion, one stripping two correct measurements out of a manual. The rule that came
out of it costs a recount and buys the difference between a repair that satisfies a report and a repair
that fixes a problem.

**Step 0a, second measurement.** The head of this release -- clock start to a pushed tag -- was
**4m 57s**, against 5m 25s, 5m 12s, 5m 36s and 5m 02s at the four before it. Five consecutive releases
inside a thirty-nine second band. The cut's own test gate ran 43 suites in **158s** against the 218s
that had been the head's floor; that is a single measurement on an otherwise idle machine, and the
suite split landed between the two, so it is reported as an observation rather than as a trend. About
two minutes of the head blocked a person: naming the release and reading the assembled notes before the
push. That is higher than the roughly forty seconds of recent releases for one reason worth naming --
the release was named by asking rather than by deciding alone, which is a choice about the release, not
a cost of the procedure.

## What was still open at this release

- **This document has no end-to-end total yet.** A release note cannot time its own publication: its
  own gates, its merge and the publish all run on the file being written. The total is added afterwards
  in its own small edit, and the copy attached to the GitHub Release carries the head only. That
  attachment is deliberately not replaced -- an attachment is what was published at the moment it was
  published. This page is the current version.
- **This release has not been published to the organisation.** Publishing is a separate decision from
  cutting and has not been asked for. Until it is, colleagues installing internally remain on the four
  team plugins at **4.11.0**, one release behind this one. Read at the target rather than carried
  forward from the previous note -- `BWJ-ecommerce/claude-plugins-bwj`, commit `d528567`,
  2026-08-15T15:44:13Z, taken from the published `plugin.json` files themselves.
- **Two specialists are *degraded* rather than excluded in the Claude App setting.** Two agent
  definitions name a script in one step of one procedure. Excluding them would lose a whole specialist
  over one line; publishing them silently hands a user a step that cannot run. They travel with that
  step named in their own description, which is a mitigation rather than a fix. Unchanged since v4.10.0.
- **A second `Get-JsonField` remains, deliberately.** No live misbehaviour was found; the risk is a
  future caller relying on a `-Default` the second copy does not have. Every available repair either
  dot-sources 1,274 lines of report machinery into a publishing script or changes the default across
  eighteen call sites. Named and left, per this repo's standing rule about risks that have not bitten;
  the reasoning is on issue `#707`.
- **310 uses of "workshop" as a role word were measured and left standing.** They are not the retired
  framing -- `workshop root`, `workshop-side` -- and sweeping them is a prose-sensitive rewrite across
  61 files of shipped plugin content that buys consistency at the price of worse sentences. Filed as
  `#720` with its measurement rather than swept along unasked.
- **Two layers of this repo speak Dutch where no path-scoped rule can reach them** -- the public GitHub
  repository description and the `inbound` label description, both in repository settings rather than
  in the tree. Outward-facing configuration, so they wait on Dave.
