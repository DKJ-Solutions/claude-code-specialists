# Release notes v4.28.0 🚀

**Date:** 2026-08-31\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

Add the workflow-bwj plugin, and harden the release gates and measurement tools for other locales and checkouts

## What changed

**No action needed unless a line below names your situation.** Nothing here is breaking and no
convention is retired. The new `workflow-bwj` plugin is opt-in and changes nothing until a repo
adopts it. Update the plugin and the rest applies on its own.

### A named way to run the gates on a commit that never opens a PR

`open-pr.ps1` now takes `-GatesOnly`: it runs your lint gate and every test suite against the working
tree and stops there -- no branch check, no push, no PR. Use it for the commits your workflow makes
directly on `main` under a named exception, the release-notes commit being the one you type by hand.
Before this, that step told you to run the gates "as `open-pr` would" -- and `open-pr` refuses on
`main` long before it reaches a gate, so you had to assemble the call yourself. That hand-built call
goes green while quietly skipping any test suite that is not PowerShell and running a hardcoded lint
script instead of your `Get-LintScript`. `cut-release`'s step 4, the `open-pr` skill page and
`CONTRIBUTING.md` §4.6 all name the flag now.

### If your work arrives from someone else's tracker: three new ticket-work rules

`CONTRIBUTING-portable.md`'s ticket-work section gains rules 11, 12 and 13: keep the judgment at the
gate rather than with the evidence, give every gate its own message with no question in the closing
one, and follow three rules when a message goes to a person. Rule 12 is the one that changes what you
may do: a delivery message may not carry a question. It comes with its measurement -- over six
tickets, five delivery messages asked a question, two of them with no question mark anywhere, and two
of the question marks that were present were `?page=` and `?sort_by=` in a URL, so the check you reach
for first does not catch it. A repo whose work does not come from an upstream tracker reads none of
this.

### On a Windows or CRLF checkout: re-read any always-on cost figure you took before

`measure-always-on.ps1` now names the unit of its byte column, and where any document on the measured
path is CRLF it prints the LF size beside the on-disk one -- per document and as a total -- with a
note that the LF column is what the next reader will compare against. The column itself is unchanged
(`Get-Item .Length`, the working copy a session actually loads). If you measured always-on cost on a
checkout with no `eol=lf` in `.gitattributes`, the old figure ran about one byte per line high --
roughly 1.4% on a 1,300-line file, enough to reach a folded changelog entry and need a correcting PR.
Re-run it and compare the LF column.

### Your test-gate runtime now reads correctly on a non-US locale

The test gate (`open-pr`, `ship-pr`, `cut-release` and CI all run it) now formats its
elapsed-seconds figure through the invariant culture. On a machine where `.` is the thousands
separator, a run over 1000 seconds printed something like `2.182s` for a run that actually took
2,182 -- a thousand times too fast, and plausible. It was latent below 1000s, which is where every
figure this gate had ever printed sat. Nothing to do; the fix arrives with the plugin.

## What it is worth

**The two BWJ store repos get a ticket procedure that maintains itself.** `workflow-bwj` packages one
rule so `smartwatchbanden` and `xoxowildhearts` cannot drift on it: an issue is filed on GitHub
first, mirrored to Asana as a colleague-facing task on a fixed skeleton, cross-linked both ways, and
closing the GitHub issue resolves the Asana task automatically. A maintainer there files once; the
colleague-facing side does not need a second hand. It is additive -- it touches only the
ticket-work step and decides nothing about branches, the pre-PR bar, or releases -- so it is the
first concrete answer to the long-standing "second workflow" question without disturbing the first.

**Three ways the tooling could hand a consumer a plausible wrong number are closed.** Each of the
gate and measurement fixes had already cost a real correcting PR: a runtime that looked a thousand
times better than it was at the one moment it mattered, an always-on cost figure inflated by a byte
per line on a Windows checkout, and a gate run for a direct-on-`main` commit that silently skipped
part of the suite. A wrong measurement is expensive precisely because it is believed; removing it at
the source is worth more than documenting it as a quirk.

**A documented route that did not exist now does.** `-GatesOnly` means the release-notes commit's
gate run is the real one -- the same function the PR path calls, through the same seams -- rather
than a hand-assembled approximation that a reader on a mixed-language test suite could not tell was
incomplete.

## What was still open at this release

`workflow-bwj` ships its plugin only. Connector registration in `connectors/` and the consumer-side
adoption both wait for each BWJ store repo's own PRs -- a settings PR to register the connector, and
an adoption PR carrying the `ASANA_PAT` secret -- which land in those repos, not here. The
one-vs-two Asana projects question is `Get-AsanaProjectGid`'s to answer per repo.

One branch, `docs/testrun-series-tail-1168-v1`, is parked live work and is not part of this release.
