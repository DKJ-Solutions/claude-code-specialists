# Release notes v4.25.0 🚀

**Date:** 2026-08-30\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

Testrun 3's findings land: four pages that contradicted their own tree, a pasteable settings proposal, and two backslash-aware un-escapes

## What changed

### Adopting the specialists is now one file replacement -- and the file you must not paste says so

**Action needed if you are setting up a new repo.** `specialists-init` now writes
`.claude/settings.proposed.json` beside the annotated `.jsonc`: your repo's own `.claude/settings.json`,
key for key, with both permissions halves already folded in. Replace one file with the other and you are
done -- no hand-merge, no comments to strip.

**Action needed if you have a habit of pasting the `.jsonc` whole: stop.** That file does not contain
`enabledPlugins` or `extraKnownMarketplaces`, so overwriting `settings.json` with it deletes both. The
symptom is that nothing happens: no skills, no subagents, no session-start messages, and a settings file
that parses perfectly. If you have ever seen a repo go quiet after adoption, that was this. The `.jsonc`
now carries the warning and names the two keys that must survive.

Where your `settings.json` cannot be read whole -- it does not parse, or its `permissions` block is not
the expected shape -- the merged file is **not** written. The run tells you which shape it found and
falls back to the hand-merge, naming those same two keys. A hook command containing a Windows path now
also survives the write byte for byte.

### If you keep your release list by hand, check which file it is in

**Action needed if you added release rows to `contributing-davekjohn/releases/README.md`.** The
scaffolded `CONTRIBUTING.md` used to call that file the release list. It is not: the list is
`releases/history.md` beside it, and it is the one document the scaffold deliberately does not write for
you. Rows added to `README.md` are rows `cut-release` never reads, so your `history.md` stays empty while
looking maintained and the cut warns about a path you were told was the wrong one.

Nothing refused and nothing broke, which is why it was worth repairing. Move any hand-added rows to
`history.md`; the scaffolded page now says all of this outright.

### The yellow `[RECORD-SHAPE]` line at session start no longer accuses a correct setup

**No action needed** -- this is a false alarm going away. If your plugins are installed machine-wide,
every session start greeted you with *"what is wrong is the administration"*, and you had to read two
lines further to learn it applied to nothing. Both headlines now report what they observed and leave the
verdict to the detail lines underneath, which are the only lines that can answer it.

Every check still fires and every remedy is still printed -- the false headline is gone, not the
coverage. Reported from a fresh consumer repo as
[#1130](https://github.com/DaveKJohn/claude-code-specialists/issues/1130) and repaired one line wider
than reported: the report named the check's roll-up, and the line you meet *first* is the hook's own
verdict above it, which made the same claim.

### The contributing cycle now starts where your work starts

**No action needed.** `CONTRIBUTING-portable.md` opened at the branch step, one step after the cycle it
describes actually begins. It now opens at *New issue or task*, with a human and Claude route that are
two kinds rather than two sub-steps, and the remaining steps renumbered 2 to 6.

The separate `TICKETWORK-portable.md` page is gone, folded into that document as its own section, and
reachable from the step it belongs to. Nothing to migrate: no script, gate or seam changed, and a repo
where nothing arrives from an upstream tracker skips that section exactly as it skipped the page.

## What it is worth

**One adoption failure mode is closed, and it was the expensive kind: silent.** Setting up a repo is a
once-per-repo job done by hand by a person, and until this release one wrong-but-reasonable move in it --
pasting the annotated settings file over the real one -- switched off everything that had just been
installed, with a valid file and no error anywhere. Measured in a fresh repo: 3 hooks, 6 skills and 15
subagents to zero across one restart. Time lost to that is not five minutes of re-reading; it is however
long it takes somebody to doubt the install rather than the file they pasted. The step is now a single
replacement, and the trap says what it would destroy.

**The rest of this release is documentation catching up with its own tree, and that is the trend worth
naming.** All five findings behind it came from one adoption round on a fresh repo, and four of the five
were pages describing an arrangement their own repo does not run. Nothing in the mechanics failed: no
gate let anything through and no script produced a wrong artefact. What cost the reader time was being
told the wrong thing confidently -- twice in a way that sent their work into a file nothing reads.

**Reduced dependence on a developer:** the session-start noise that a machine-wide install produced at
every single start is gone, so a yellow line in that output means something again. A check that cries
wolf every day is a check people stop reading, and getting that back costs nothing per session but is
only earned by keeping the headline honest.

## What was still open at this release

**Three things, all recorded, none blocking.**

- The `[RECORD-SHAPE]` **predicate** was deliberately left alone -- only its wording changed. Whether a
  plugin your repo's own settings never enabled should count toward that roll-up at all rests on a fact
  nobody has measured yet, and gating on it unmeasured would restore exactly the silence the check was
  built to end.
- Two defects found while cutting this release were filed rather than fixed in it:
  [#1139](https://github.com/DaveKJohn/claude-code-specialists/issues/1139) (resuming a branch parked
  from another device creates a second branch instead of continuing it) and
  [#1140](https://github.com/DaveKJohn/claude-code-specialists/issues/1140) (a comment in the release cut
  states a version-bump rule that was loosened three weeks ago).
- The fourth adoption round is planned but not run. Its plan is written and waiting; it targets three
  paths no round has reached -- a tier-2 audience note, a major version cut, and a repo with no remote.
