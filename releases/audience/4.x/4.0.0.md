# Release notes v4.0.0 🚀

**Date:** 2026-08-09  
**Type:** Major  
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

**If you are already on `v3.10.0`, there is nothing for you to do.** The major bump marks a milestone,
not an incompatibility — everything below arrives on its own with your next update.

**If you are on anything earlier, stop and read the next section first.** Chapter 3 contains two changes
that break an existing installation, and neither of them produces an error message. A mechanical update
from an older version leaves you with a session that starts normally and has nothing behind it.

## For consumers

### Start here if you are updating from `v3.9.0` or earlier

Work forward from wherever you are. Each of these is a page of its own, because each one asks something
of you that a rename cannot do on your behalf.

#### 1. From before `v3.2.0` — the marketplace was renamed

**The symptom:** commands that name the old marketplace stop resolving. Nothing errors; the name simply
no longer exists.

Start at [the `v3.2.0` notes](../3.x/3.2.0.md) and do not run any install command until you have.

#### 2. From before `v3.8.0` — the workflow became opt-in

**This is the one decision on the list that only you can make:** whether you want a workflow at all.
Before `v3.8.0` you got one whether or not you had asked; after it, you choose.

See [the `v3.8.0` notes](../3.x/3.8.0.md).

#### 3. From before `v3.10.0` — every plugin was renamed

**The symptom:** your session starts normally, with no specialists in it. The old plugin ids no longer
exist, an unresolvable id is dropped silently, and nothing anywhere says so.

Read [the `v3.10.0` notes](../3.x/3.10.0.md) **before** running any command. There is a choice in it
about which workflow you end up with, and a mechanical rename will not surface it for you.

### Update

```powershell
claude plugin marketplace update claude-code-specialists
```

**Run that first, every time, and make a habit of it.** A `github` marketplace source is a cached clone.
A stale cache reports success and shows you a plausible version number, so there is no output you could
read to catch it.

### What you get

#### Your pull requests read better

A PR body used to open with four lines of bookkeeping — the title repeated from the heading directly
above it, a creation timestamp, and a type already shown to you as a label — before the first sentence
about the change. It now starts at that sentence, and its headings sit at the levels a standalone
document uses. You get this through the workflow plugin; nothing on your side changes.

#### If you adopted this release workflow, you were allowed to publish more than the page told you

The page describing how releases work — the one you copy — stated rules **stricter than the software
actually enforces**. It claimed a release needed something in it for a colleague before it could be cut
at all, and something a *user* would notice before it could be a minor. Neither is true.

So if you read that page and concluded some piece of work was not allowed out, it was. The page now
matches what the code does, including the rule that **a release with nothing to announce is exactly what
a patch is for**.

#### Four other claims were corrected, and three directories now have a page

The most visible: a list that called itself the complete set of shared scripts while showing nine of
twenty-three. Three directories that had never been documented now have a page each, including the one
where the shared scripts are maintained.

### What `v4.0.0` is

A line under chapter 3. Over that chapter the specialists stopped bringing a way of working with them,
and every plugin became either a **team** — who your colleagues are — or a **workflow** — how work moves
through your repo. Teams stack; you enable exactly one workflow, or none.

The two chapter-3 releases worth reading are [`v3.2.0`](../3.x/3.2.0.md) and
[`v3.10.0`](../3.x/3.10.0.md): the two that break an existing install.

## What it is worth

> **This release asks nothing of you -- but the version you are updating *from* might.** A major bump is
> a milestone here, not an incompatibility. The chapter it closes, however, contains two changes that
> break every existing installation **without producing an error message**: the marketplace was renamed,
> and later every plugin was.

**The instructions we hand other teams now match the software they describe.** This is the item with real
exposure: a set of release rules that is stricter than reality does not fail loudly — it quietly stops
someone from shipping, and they have no way to know the document is the thing that is wrong. That class of
error was found in the one document written to be copied by others.

**Review time moved from bookkeeping to substance.** Every pull request from here starts at the argument
instead of at metadata the page around it was already showing. Small per review, and it applies to all of
them.

**A recurring session-level false alarm is gone.** A check that cries wolf every session against a correct
setup is worse than no check, because it teaches the team to scroll past the place real problems appear.

**The habit is the durable part, and it now runs in both directions.** Documentation here is increasingly
verified against the system rather than re-read — which is how a "complete" list turned out to be
nine-of-twenty-three. The same discipline is what allowed a well-intentioned new safeguard to be refused on
evidence, and the refusal to be written down so the next person does not spend the same afternoon
rediscovering it. Saying no with numbers is cheaper than maintaining a check that is wrong a hundred and
twenty-four times.

## What was still open at this release

**A snapshot, at the moment of the cut.** The consumer-facing highlights and this summary were the two
documents the release tooling deliberately leaves to a person; both were written after the version was
tagged and shipped together through the normal review route, with the public release page published after
they landed. Nothing else was left open, and no decision was waiting on anyone outside the team.
