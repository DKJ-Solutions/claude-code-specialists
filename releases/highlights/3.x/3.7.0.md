# Release notes v3.7.0 🚀

**Date:** 2026-08-07  
**Type:** Minor

The two files a branch works in got the shape they were designed for. The changelog entry became the
branch's own dossier, the step list holds the plan and nothing else, and the guidance that used to fill
both files now lives beside them in `branch/templates/` — so what you type in is the questions and your
answers.

**Nothing in this release needs anything from you.** Your next `new-branch` writes the new shape by
itself, and every branch already in flight keeps working: all the older forms are still read, on purpose.

---

## What your next branch looks like

`branch-changelog.md` is now a form with six sections. Three of them are filled in for you — the heading
names the branch, and the ID and type are stamped when the branch is created:

```markdown
## `feat/your-branch` changelog

### Branch description

### Branch ID

### Branch type

### What does the change on this branch bring to main?

### Significance

### Pull Request
```

`branch-progress.md` is the other half and got shorter rather than longer: a heading, `### Steps`, and
`### Where I left off`. It no longer repeats the description, the ID and the type — those are the entry's,
and having them in both files meant two places that could disagree.

**Neither file carries explanatory comments any more.** The full form, with the guidance for every field,
is in `branch/templates/` — open those when you want to see what a good answer looks like.

## Every change now answers all three tiers

`### Significance` holds a `#### Tier 0`, `#### Tier 1` and `#### Tier 2` sub-section, and each one is
answered. Where a change genuinely reaches nobody at a tier, you write **`N/A`** and one line saying why:

```markdown
#### Tier 2

Only this repo's own scripts read it; no consumer can observe the change.

**Score:** N/A
```

Tier 1 and tier 2 used to be left out when they did not apply, and their absence *was* the claim. That
could not be told apart from an unfinished entry — so nothing could distinguish "this reaches no consumer"
from "nobody has got to tier 2 yet", and those need opposite responses. Answering costs a sentence and
keeps the reasoning behind a *negative* claim, which the old shape discarded.

**How far a change reaches is now the highest tier carrying a number.** An `N/A` does not count towards it,
and the cumulative ladder still holds: `N/A` at tier 1 under a scored tier 2 is refused, because a change
consumers notice is also one your colleagues get something out of.

## The gate measures instead of matching

There is no visible `TODO:` anywhere in the scaffold now, so `open-pr` no longer looks for placeholder
text. It reports **unanswered fields** — the description, the body, and any tier still missing its reason.
That catches strictly more than the old string matching did: both the entry nobody touched and the one
whose prompt was deleted rather than answered.

## Compatibility

Everything written under an older shape is still read, deliberately and permanently:

- the retired section headings (`What does this change do?`, `Type of change`, `Who is this for`);
- the plain `Score:` alongside the bold `**Score:**`;
- the impact table, and the `Tier: N` line that preceded it.

You receive these scripts through a plugin update rather than by choosing to, so a branch you opened
yesterday folds exactly as it did before.
