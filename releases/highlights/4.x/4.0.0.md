# Release notes v4.0.0 🚀

**Date:** 2026-08-09
**Type:** Major

**Nothing in this release needs anything from you.** The major bump marks a milestone, not an
incompatibility — it closes the third chapter of the Claude Specialists. Everything below arrives on its
own with your next update.

**The one thing worth checking is where you are updating *from*.** Chapter 3 contained two changes that
break every existing installation, and both fail in silence. If you have not made either move yet, the
sections at the bottom of this page are the ones to read — not this one.

---

## Update

```powershell
claude plugin marketplace update claude-code-specialists
```

Run that first. A `github` marketplace source is a cached clone, and it is worth making a habit of: a
stale cache reports success with a plausible version number, so there is no output you could read to
detect it.

## What this release is

`v4.0.0` draws a line under **twenty-one releases and fifty-one pull requests in ten days**. Over that
chapter the specialists stopped bringing a way of working with them, and every plugin became either a
**team** — who your colleagues are — or a **workflow** — how work moves through your repo. Teams stack;
you enable exactly one workflow, or none.

The full recap is in the [release notes](../../development/4.x/4.0.0.md).

## What actually changed in this release

This one is documentation catching up with the product, and it was done by holding each document against
the code rather than re-reading it. Three things follow for you.

**The page describing how releases work — the one you copy if you adopt this workflow — was wrong on five
points, all in the same direction.** It stated release rules **stricter than the software enforces**: it
claimed a release needed something for a colleague before it could be cut at all, and something a *user*
notices before it could be a minor. Neither is true. If you read that page and concluded you were not
allowed to publish some piece of work, you were allowed. It now matches what the code does, including the
rule that a release with nothing to announce is exactly what a patch is for.

**Four other claims were corrected against the tree they describe** — most visibly a list that called
itself the complete set of shared scripts while showing nine of twenty-three. And three directories that
had never been documented now have a page each, including the source directory where the shared scripts
are actually maintained.

**Your pull requests read better.** A PR body used to open with four lines of branch bookkeeping — the
title repeated from the heading above it, a creation timestamp, a type already shown as a label — before
the first sentence about the change. It now starts at that sentence, and its headings sit at the levels a
standalone document uses. You get this through the workflow plugin; nothing on your side changes.

**One proposed check was measured and declined**, and that is recorded on purpose rather than quietly
dropped. The idea — flag any file path in prose that does not exist — was built five ways and run over a
hundred and twenty documents. The narrowest version raised a hundred and twenty-four alerts and none was
real, because most paths this product names correctly describe *your* repo rather than its own.

## If you are updating from before v3.10.0

**Every plugin was renamed, and your existing install stops resolving.** Nothing errors — the old ids
simply no longer exist, and your session starts normally with no specialists at all. Read
[the v3.10.0 notes](../../highlights/3.x/3.10.0.md) before running any command; there is a choice in it
about which workflow you end up with that a mechanical rename will not surface for you.

## If you are updating from before v3.2.0

**The marketplace itself was renamed**, with the same silent failure mode. Start at
[the v3.2.0 notes](../../highlights/3.x/3.2.0.md).

## If you are updating from before v3.8.0

**This is where the workflow became opt-in**, and it carries the one decision in recent history that only
you can make: whether you want a workflow at all. See
[the v3.8.0 notes](../../highlights/3.x/3.8.0.md).
