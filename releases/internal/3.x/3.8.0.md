# Internal summary v3.8.0

**Date:** 2026-08-08
**Type:** Minor
**For whom:** colleagues and management -- what the organisation gets out of this release

## What is different now

- **The product stopped shipping one person's way of working to everyone.** The branch, changelog and
  release machinery moved out of the shared core into a separate plugin a repo switches on by choice.
  A repo that adopts the specialists now gets colleagues; it no longer inherits a workflow, a set of
  configuration files it must fill in, or a session check that called it misconfigured for differing.
- **The specialists adapt to the repo they land in.** They read how that repo already works before
  reaching for the conventions of the repo they were built in.
- **One product, one changelog.** Ten generated files carrying a duplicate history were removed, along
  with the two gates that existed to keep the duplicate agreeing with the original.
- **The safety gates got faster and cover more.** The test suite runs in parallel -- about three times
  quicker -- and a release now passes the same full gate every ordinary change does, closing a gap
  where the release was the least-checked step in the process.

## What it is worth

**The product can now be adopted by a team that does not work the way we do.** That was the real
barrier, and it was invisible while we were the only consumer: 47% of what the core sent was workflow
machinery rather than expertise, so "install this" meant "and also work like this". Removing that
condition widens who the product is for without weakening what it does for the repos already using it.

**It also lowers the cost of every future addition, because the question is now decided at the door.**
Each new thing is either a craft, which travels, or a way of working, which is opt-in. That single test
replaces a judgement that was being made case by case and, measurably, not being made consistently.

**And the gates cost less time while catching more.** The suite that runs before every change dropped
from roughly eight and a half minutes to about two and a half, and the release step -- the one that
publishes -- is now covered by it rather than by a lighter check.

## What was still open at this release

The changelog's own introduction had drifted out of date and was found during the release inspection --
it still described a document shape and a version-bump rule that were replaced earlier this month. It
passes through each release untouched, so nothing was checking it. Recorded for repair; nothing depends
on it beyond readers of that file.

Two consuming repos, life-hub and smartwatchbanden, were several versions behind at the time of this
release and had not yet been updated. Whoever works in those repos next picks that up from their own
session start.
