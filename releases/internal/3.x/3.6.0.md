# Internal summary v3.6.0

**Date:** 2026-08-06
**Type:** Minor
**For whom:** colleagues and management -- what the organisation gets out of this release

## What is different now

- **Every change now says how far it reaches and how much it weighs, and the release documents order
  themselves by it.** Until this release the changelog was grouped by the kind of branch a change arrived
  on. That was measured against the previous release and does not survive contact: the single most
  consequential change for users -- one that broke every existing installation -- arrived on a branch
  labelled routine maintenance and was therefore filed third. The author of a change now scores it
  against a written five-point scale, and the most consequential change leads.

- **A release has to earn its version number.** The tooling refuses to cut one that the pending work does
  not justify: a release nobody outside this project would notice, a feature release with nothing a user
  notices, or a major release without ten smaller ones behind it. When it refuses, it names the version
  the work does earn. That judgement used to rest on whoever happened to be cutting.

- **A branch has to finish the plan it wrote for itself.** Work now records its own steps at the moment it
  starts, and cannot be proposed or merged while a step is still open. There is a third mark for a step
  that turned out not to be needed, with the reason kept on the line -- deliberately, because the only
  alternative is teaching people to tick work they never did.

- **Removing this system from a project could delete work somebody had written.** Reported from outside,
  measured in a project where three filled-in documents holding 153 lines were all classified as
  disposable scaffolding. Fixed. Projects set up before this release need one manual pass to be safe; the
  release notes say which.

- **The adoption documentation is two pages instead of three**, and no longer recounts its own version
  history to someone who is trying to install for the first time.

## What it is worth

**The question of what matters most moved from a reader to the author, at the one moment it can be
answered cheaply.** Ranking twenty-two changes after the fact means re-reading twenty-two changes; the
person who wrote one knows what it was worth in the minute they wrote it. The scale is written down rather
than left to instinct, which is what makes the numbers comparable between releases instead of a mood.

**Three judgements that used to depend on someone remembering are now checked.** Whether a version number
is deserved, whether a branch finished what it set out to do, and whether a release document is ordered by
consequence -- each was a habit, and each is now refused when it is not met. The value is not the checking
itself but that the failure is loud: all three used to fail silently, which is the expensive kind.

**And the release process asks for approval one time fewer.** Cutting a release is still a deliberate
decision. The closing steps of a cut that was already asked for are no longer a second decision, because a
checkpoint that is always waved through trains people to stop reading the ones that are not.

## What was still open at this release

- The user-facing release document is still generated as a draft and rewritten by hand before publication.
  The selection of what belongs in it is now automatic; the prose is not, and was not intended to be.

- Two things surfaced while cutting this release and were recorded rather than repaired. A safety check
  cannot tell a quoted example from a real occurrence, and flagged a text that merely described the
  problem it looks for -- the fifth time this project has met that same shape. And seven of 326 dated
  entries in the published history disagree with the real date by a day or two; they were deliberately
  left alone, because they sit in records that have already gone out and moving them rewrites shipped
  history for nobody's benefit. Whether either becomes work sits with Dave.

- The empty-section defect this release nearly shipped was caught by the one step where a person looks at
  the assembled document before it is public. That step is optional in the tooling. Whether it should stay
  optional was not decided here.
