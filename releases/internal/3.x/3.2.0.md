# Internal summary v3.2.0

**Date:** 2026-08-03
**Type:** Minor
**For whom:** colleagues and management -- what the organisation gets out of this release

This release has two halves. One is a rename and reorganisation that every existing user has to act on
once. The other is the quieter and more valuable half: work that existed three times now exists once,
and four checks that reported "fine" without looking have been repaired.

## What is different now

- **The product is named after what it is.** It was presented as a workshop that would eventually house
  every future tool; it turned out to be one product, so it is now named and organised as one. Two empty
  organisational layers disappeared with it.
- **The shared toolset covers the whole workflow instead of half of it.** Opening a change, merging it,
  cutting a release and writing its notes were each maintained separately per project. They are now one
  set that every project draws from, with the differences between projects declared per project rather
  than forked into a second copy of the script.
- **A release is now written for three different readers.** The full technical record, a version for the
  people who use the product, and this summary. One document was serving all three, badly.
- **Four checks that reported success without checking have been repaired.** The most serious could
  silently switch off the entire specialist layer: a missing central file was reported by nothing, so a
  session would simply run without it. Another had been reading far more than it claimed to read for
  months.
- **Instructions that could not be followed have been corrected.** Five documented promises did not hold
  when someone actually walked the path -- including a card that told readers which version they were
  running, which was usually wrong.
- **Two reporting figures are now measured rather than counted by hand.** Both had been wrong in the
  papers of the round that was checking them.

## What it is worth

- **Maintenance that was paid three times is now paid once.** The release and review workflow was
  duplicated across projects; an improvement had to be made in each of them, or the copies quietly drifted
  apart -- which is exactly what had happened. From now on an improvement reaches every project through an
  update instead of through repeated manual work.
- **Less false confidence, which is the expensive kind.** A check that reports a problem costs an hour. A
  check that reports success without looking costs whatever is built on top of it before anyone finds out
  -- and nobody goes looking behind a green result. Four of those are gone.
- **Someone can start using this without help.** The installation page was thorough and therefore
  unusable as a first step; it is now split into a short path and a reference. Three separate people
  getting stuck in the same place is what prompted it.
- **A working rule was written down that had cost real repairs.** A report says both what went wrong and
  why, and the second half is a guess by whoever measured from the outside. Acting on that guess produces
  a fix that satisfies the report and is wrong -- which is worse than the original problem, because it now
  carries a justification. The reason gets verified first.

## What is still open

- **Every existing user has to reconnect once.** The rename means installations point at a name that no
  longer exists. Nothing errors -- it simply stops loading -- so this is documented rather than fixable
  from our side. No release can do it for them.
- **The user-facing version of these notes still needs an editorial pass.** The draft is generated, and
  the automatic split between "what a user notices" and "internal detail" puts the three most important
  items on the wrong side in this particular release. That is now written down as a warning rather than
  trusted.
- **One project still runs its own copy of the release tooling** until it picks up this version. The
  duplication is removed at the source; the last step is on that side.
- **One reported observation is deliberately not acted on.** It was seen once and has not been reproduced,
  and the report asks for reproduction first. Repairing an unreproduced symptom is how the wrong cause
  gets a citation.
- **One known cosmetic defect in generated release notes is unresolved.** It is recorded where the next
  person will meet it, with what has and has not been ruled out; the cause is not isolated yet.
