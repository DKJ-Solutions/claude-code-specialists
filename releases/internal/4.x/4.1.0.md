# Internal summary v4.1.0

**Date:** 2026-08-10
**Type:** Minor
**For whom:** colleagues and management -- what the organisation gets out of this release

> This release asks nothing of you to keep working. It does contain **three checks worth running against
> your own repo**, because each one is about state that may already be wrong there rather than about
> anything this release changes underneath you. They are listed with the exact commands in the notes for
> users attached to this release.

## What is different now

- **A silent failure in the pull-request tooling became a loud one.** When a repo's PR template drifted
  by even one word, every pull request it opened lost its description and nothing said so. One repo
  merged twelve of its last sixty that way before anyone noticed. The run now warns and names the repair.
- **The way of working can be adopted rather than re-derived.** The contribution cycle and the shape of
  the PR template now travel with the product, written to be read in any repo instead of stating one
  repo's answers as the rule. A repo adopting this no longer has to reverse-engineer the cycle from
  scripts, and four statements that were measurably false outside the source repo are gone.
- **Three seams that answered wrongly in silence were closed or made visible.** All three shared one
  shape: a shared script reads a repo's answer, has a sensible default, and a wrong answer degrades
  quietly -- discovered by accident months later.
- **A fold now says it is a fold.** The commit that files a merged change into the changelog is typed
  `fold:` rather than `chore:`, so the history reads as what it is. Nothing reads that line, so nothing
  needs migrating.
- **Anyone still on the previous major has a written migration path.** The `v4.0.0` rename broke two
  things inside a consuming repo without producing an error message. Both now have a before/after, along
  with the reason no tool repairs them automatically.

## What it is worth

**The theme of this release is failures that produce no error message**, and that is where the value sits.
Twelve pull requests with an empty description is not a crisis on any single day; it is a record that
quietly stopped being usable, found by comparing two files months afterwards. The same shape appeared
three times in one week across different seams. Each repair here converts one of those into something a
person is told about at the moment it happens -- which is the difference between a five-minute fix and an
archaeology exercise.

**The second half is about dependence.** Adopting this way of working in a new repo used to mean reading
someone else's scripts and guessing which of their answers were rules and which were preferences. That
work now ships as a document written for the reader rather than for the author, with the seams named. The
measurable claim is narrow and deliberate: the two documents that a repo previously had to reconstruct by
hand are now copied and edited instead.

**And one principle was made explicit rather than assumed**, because it decides how the rest of this
transfers: what travels between repos is the **measurement**, not the answer. This repo removed its PR
checklist after counting sixty pull requests and finding no box that carried information. The repo that
prompted this release ran the same count and correctly kept one -- an approval that only a human eye can
give. Shipping the conclusion would have cost them that box.

## What was still open at this release

- **Two follow-ups were deliberately declined rather than deferred**, each with the reason recorded: a
  pre-written "specific to this repo" section in the shipped PR template (every heading there repeats in
  every pull request body, so an empty one is permanent noise), and extending the configuration-adoption
  command to offer files as well as functions -- worth its own change if a consuming repo asks for it.
- **A consuming repo's own template is checked by nothing.** The new gate runs in the source repo. What
  reaches a consumer is the warning at the moment they open a pull request, and a reference file to
  compare against. Closing that properly would need a check on their side, and no one has asked for one.
- Nothing else was left half-done; every change in this release merged with its gates green.
