# Release notes v4.33.0 🚀

**Date:** 2026-09-10\
**Type:** Minor\
**For whom:** consumers of this product, and the organisation -- one section each

## What changed

### You must act: the team plugins are renamed

The four team plugins are now `dkj-subagents-alpha`, `dkj-subagents-ecomm`, `dkj-subagents-lifehub`
and `dkj-subagents-shopify` (they were `dkj-team-*`), and their directory is
`plugins/dkj-subagents/`. `dkj-policy` and `dkj-policy-bwj` keep their names.

**A rename is not a `claude plugin update`.** On every machine:

1. Uninstall the four `dkj-team-*` ids and install the `dkj-subagents-*` ids. This rewrites your
   `enabledPlugins` for you.
2. Fix the `@`-import in your `SPECIALISTS.md`: the full marketplace path moved on both halves
   (`dkj-teams/dkj-team-alpha` becomes `dkj-subagents/dkj-subagents-alpha`).
3. If you keep a `connectors/` register, update the plugin ids in it. An unresolvable id makes
   `check-connectors.ps1` skip that plugin's whole drift check without saying so.

The family's `INSTALL.md` carries the exact command sequence as its third migration section. Until
you do this, an unresolved `@`-import fails **silently** -- the orchestrator loads without his ritual
and his routing rules, the roster renders around the hole, and nothing on screen says anything is
wrong.

Your plugin listing also shows new labels -- `(subagent scaffold)` and `(policy scaffold)` -- but no
plugin id there changed and nothing else needs touching.

### Behaviour changes worth knowing -- nothing to migrate

- **A dispatched subagent can no longer move your working copy.** A `PreToolUse` hook in `dkj-policy`
  now refuses `git checkout`, `stash`, `reset`, `restore`, `switch`, `clean` and ref mutations when
  they come from a dispatched subagent; your own session's identical command is untouched. This
  closes a hazard that discarded uncommitted work with no error and a clean `git status` afterwards.
  It costs roughly 440 ms on every `Bash` / `PowerShell` call in a session that dispatches subagents
  (about 400 ms of that is the `powershell` launch every command hook already pays).
- **`perl -c "..."` containing a theme publish, delete or live push is now refused** by the Shopify
  live-theme guard. This is a known false positive -- `perl -c` only syntax-checks -- and the price
  of the guard handling command wrappers explicitly. `perl -e` is unchanged.
- **A broken Shopify guard install now fails safe.** With `command-guard-lib.ps1` missing, the guard
  keeps blocking (matching the whole command, without the authoring exemptions) and names the file to
  reinstall on stderr, instead of behaving unpredictably.

### Opt-in: a shorter PR cycle by trusting CI

`open-pr` can now skip its local test suites when the trunk's required check is already green on the
exact commit it would ship -- on this repo that was a ~30-minute redundant run per change. It
**arrives switched off.** Turn it on by naming your test check in `Get-CiTestCheckName`
(`scripts/repo-config.ps1`); the adopt blueprint offers the line like any other seam. Every ambiguity
-- no declared name, a stale PR head, an empty required set, the check not green -- runs the full gate
as before, so a plugin update cannot quietly stand a gate down in a repo nobody has looked at.

### New: check whether this machine is on the current release

A new `dkj-policy` skill, `plugin-versions`, reports per enabled plugin whether the version
**installed in this checkout** matches the one the local marketplace clone holds, and prints the
command that closes the gap (`claude plugin update` versus `claude plugin marketplace update`).
Read-only, no arguments, runs on any device.

Session start now also gives this answer on machines with **no source checkout** beside them --
previously those said nothing at all about versions, so a session could load a plugin release behind
the machine's own with no signal of it.

### Fixes to the scripts you run

Each of these is a shipped script reaching you through the plugin mirror. There is nothing to adopt;
the common thread is that a message now tells you what actually happened.

- **`fold-changelog-entry.ps1` no longer crashes on the first fold after a release cut.** The crash
  landed between the changelog write and the commit, so `-Commit -Push` silently did neither and left
  the fold uncommitted with the entry file already gone. Every consumer's first fold after their own
  cut hit this.
- **`ship-pr.ps1` no longer loses the fold to an unrelated uncommitted file**, and no longer refuses
  a lane ship when the primary checkout holds the trunk under a merge queue. An interrupted ship can
  now be resumed from the front door -- it names the PR, the branch and the `git checkout` -- and its
  go-ahead line states what it actually did with your working tree instead of always claiming it went
  home.
- **`open-pr`'s "already done" check goes quiet unless it has something to say.** It had been reading
  the scaffold's guidance block and reporting every issue cited there as a mention of your branch. It
  also now refuses a malformed branch document -- a missing phase heading, branch content in the
  generic block -- **before** the push rather than only advisorily in CI.
- **A resumed branch learns that another session is already on it** -- at pickup and on every turn
  after -- naming how far behind you are and the other side's tip author and subject.
- **The skipped-fold session check stops raising a red `[ERROR]` for the ordinary state of being a
  few commits behind.** It gives a `[WARN]` and the `git pull --ff-only` that fixes it; a checkout
  that has drifted both ahead and behind is no longer sent at a fast-forward that cannot run.
- **Six callers of `Invoke-NativeCapture` stop turning a premature read into a wrong verdict** --
  "no PR", "no issue declared", "the section did not change" (which had refused a merge in a gate
  with no `-Force`), "the claim was refused". An empty capture at exit 0 is now reported as a short
  read, and on a clean exit the reader waits briefly for the file handle to release.
- **`claim-issue` bounds its `gh` calls** so a stalled `gh` is reported rather than waited out, and
  it tells "gh never answered" apart from "your account is genuinely not the assignee". The latter
  still refuses; the former says the claim most likely landed, says how to confirm it, and does not
  block.
- **`sync-main` reads and prints file paths correctly.** A theme file with an accent in its name no
  longer matches nothing and draws a wrong standing-predecessor verdict, and no printed remedy hands
  your shell a path or ref it would act on.
- **The `Fold on merge` CI job stands down green** instead of going red when a second merge lands
  within seconds of the first. A `Stood down:` line in the log is the job working.
- **Session start is a few hundred milliseconds faster** -- the check hooks run in the interpreter
  the harness already started instead of each spawning a second `powershell.exe`. Reports are
  unchanged, verdict for verdict.
- **A repo with no optional seams configured saves roughly a third of a second per run** of the
  shipped scripts -- the seam probe reads the function table directly instead of scanning `PATH`.
- **16 links in the plugin payload that named a file and pointed at the repository front page** now
  carry their real path, including the one `specialists-init` gives a new adopter for `INSTALL.md`.
- **`adopt-dkj-policy` Part 1 now places -- and tops up -- the UPDATE section** in your
  `dkj-policy/README.md`, even if your folder was scaffolded before that section existed. The
  `dkj-policy` plugin page itself gains an "Updating it" section: the two commands, the restart, and
  why the cached clone and the install record are per-machine state that no session reports.
- **A repo that enables `dkj-subagents-shopify` without a store** can declare
  `Get-ShopifyRepoHasNoStore` and get a clean session start instead of a standing `[ERROR]`, without
  faking a theme id.
- **The machine-local path gate's remedy names both cases** -- a machine's own extra enable belongs
  in `settings.local.json`, but a branch whose subject *is* the tracked set every clone inherits
  should keep its change.

One correction with nothing to do: the local-to-CI suite-duration ratio in the docstring of
`native-capture-lib.ps1` was stated backwards (it read as local being ~3.8x faster; a workstation
measured ~2.6x *slower*, and a third setup agreed with neither). The gate never read the number;
anyone sizing their own CI off a local run was dividing by a figure that does not exist.

## What it is worth

- **The rename removes a silent failure mode.** An unresolved `@`-import does not error -- it drops
  everything it was meant to bring in, and the roster keeps rendering around the gap. The near-miss
  that prompted the guard warning caught six new files carrying retired plugin names only by hand.
  Aligning the plugin names to what the plugins actually ship -- Claude Code's own word, *subagent*
  -- is what closes that class. The migration cost is one-time and scripted.
- **A class of "the session just sits there" and "the gate refused on the wrong thing" is closed.**
  The first-fold-after-release crash hit every release and needed a hand-typed recovery each time.
  The `claim-issue`, `ship-pr` resume, mention-scan and skipped-fold fixes each replace a wrong or
  missing message with one an operator can act on -- the failures that cost the most time to diagnose
  and the least to fix once named.
- **The dispatched-subagent working-copy guard** turns a rule that was advisory in every agent def
  into one the harness enforces. The hazard it closes -- a review or fan-out specialist discarding
  uncommitted work with no trace -- was measured 11 times in this repo's own command history, all
  real, with no false positives.
- **The PR cycle can be about 30 minutes shorter per change** on repos that opt in to the
  CI-certificate skip, with no gate relaxed: the check skipped for is the one the merge is already
  blocked on.
- **Session start is faster and quieter** -- a few hundred milliseconds off every start, resume,
  clear and compact, and the skipped-fold check no longer raises a red error for the ordinary state
  of being slightly behind the trunk.

## What was still open at this release

- **The release-title convention.** This is the first cut to use a generic `-Title` ("Release
  version 4.33.0") rather than a forced one-sentence summary, on the ground that no single sentence
  describes 97 unrelated entries. Whether that becomes the standing rule -- flat for every release,
  or a generic default only when no meaningful title is offered -- sits with Dave; a `docs/` branch
  will record the decision.
- **Publishing the marketplace to the business organisation** (the internal Block 3 step) was not
  run as part of this cut. It is a separate, deliberate decision and sits with Dave.
- **This repo's own migration to the new plugin names** is the same one-time step every consumer
  runs after this release: the `@`-import already points at the `dkj-subagents` path, and the local
  marketplace clone catches up on `claude plugin marketplace update`. Not a defect -- the expected
  order of events for a rename that ships in the release that renames it.
