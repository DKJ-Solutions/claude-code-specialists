# Release notes v4.29.0 🚀

**Date:** 2026-09-04\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

Per-branch development documents, a live work-tracker mirror, and a test gate packed by measured duration

## What changed

**Four situations need a hand, and they are the four at the top.** Everything below them arrives on the
plugin update and needs nothing from you. No convention you were told to adopt is retired without a
replacement, and no open branch has to be migrated.

### If you enabled `workflow-bwj`: rename it to `bwj-codex` in your settings

One line in `.claude/settings.json`. **Nothing migrates automatically and nothing warns you** -- a session
in a repo whose settings still name `workflow-bwj` simply loses the plugin's two skills and its CI
template reference, with no error and no missing-plugin line. If you never enabled it, ignore this.

### If you run the Asana mirror: re-copy two files, and check four labels exist

The mirror now carries the Asana priority score across as a GitHub label, which is the first thing from
the Asana side to reach your issue list. Two steps, neither automatic:

- **re-copy the two `templates/` files into `.github/`** -- the workflow needs `issues: write`, which your
  existing copy does not grant;
- **have the four labels present.** `adopt-bwj-asana` creates them. `gh issue edit` fails outright on a
  label the repo has not got, so a missing one is loud rather than silent.

### If you run the Asana mirror: number your board's sections and name the board

The board's six sections now drive the cycle's stages, so a colleague can see a request was picked up
without asking. **Two setup steps are required and both fail silently if you skip them:** each section
name has to carry a leading number, and `Get-AsanaProjectGid` has to name that board.

That second one settles a question this page used to leave open -- *one shared project, or one per store?*
There is now a single right answer: the stages live on the board's own sections and `Prio-Score` does not
cross workspaces, so the board you name must be the board in the workspace your priority field lives in.
An unrecognised column now **stops** the card rather than moving it somewhere plausible.

You may also delete `ASANA_WORKSPACE_GID` from your Actions variables -- the CI half never read it.
Nothing breaks if you leave it standing.

### One standing condition from the org move, which needs nothing today

Functional references now name `DKJ-Solutions`. **You need to do nothing:** your `extraKnownMarketplaces`
still names the old owner and the transfer redirect resolves it. What changes is what a *fresh* adoption
writes. The condition you inherit without asking for it: **the old path must never be recreated**, or every
registration still pointing at it stops resolving at once.

### One behaviour genuinely changed: the Shopify pre-task sync now refuses an unreachable origin

If you run `team-shopify`'s `sync-main.ps1`, a `git ls-remote` or `git fetch` that cannot reach origin now
**refuses the run** where it used to continue -- and that includes `-DryRun`. Nothing is written either way,
so the cost is re-running it. What you get back is that the standing-predecessor guard can no longer report
`none on origin` when what it actually means is that it could not ask.

Every network call in that script is now non-interactive and bounded. The hang this closes was fifteen
minutes on a `git push` whose credential helper was drawing a window nothing was listening to -- in the
script whose commit holds a third party's in-flight edits to your live theme, taken out of a mirror the
`finally` block then deletes. Until that push lands, the only copy of that work is a local branch nobody
is looking at, presented as a push still running.

### Your branch documents change name, and no branch is stranded

Each branch's development document is now named after its branch alone. **Nothing to migrate:** the old
names are read and never written, so a document already holding work stays where it is and is still found,
folded and cleared. Open branches keep their old name and old headings; new ones get the shorter name and
the plainer headings.

What you gain is the defect itself. With more than one PR open, **every merge to the trunk left every
other open PR conflicting on one path** -- and a conflicting PR gets no check suite at all, so it could
never go green and could never merge. If you have been seeing PRs that stall with no failing check to
point at, that was this.

The creation stamp is gone from the document heading and is not replaced; nothing ever read it back, and
the stamp the changelog orders by is the merge stamp, which is unchanged.

### `new-branch` stops rewriting the branch name you hand it

The `-v1` suffix is no longer auto-completed. You will notice it the next time you branch.

### Your ship and PR runs stop failing at the most expensive moment

Six guards moved earlier or learned to say what happened. Each of these previously landed *after* the entry
gates, the suites and the push -- or left a state indistinguishable from a parked branch:

- **`open-pr` checks the branch prefix's label exists before it pushes.** A label is a repo setting somebody
  else can change: measured in a consumer on 2026-09-01, `bug` and `enhancement` were deleted org-wide
  because the issue *type* now carries that classification, and the seam table was correct the day before.
  Now it costs one API call, lands in seconds, and names both remedies in the line that refuses.
- **`ship-pr` refuses before the merge when it cannot push the fold** -- the same step and reasoning that
  already refused when it could not *check out* the trunk.
- **`ship-pr` names a missing Actions check suite** and the reopen that restores it, stated as GitHub's own
  default `pull_request` types rather than as a claim about your workflows.
- **`ship-pr` tells a dropped CI watch from a red check** and re-enters the wait, instead of sending you to
  look at CI that was fine. Before this a dropped socket cost you a re-checkout of the branch the ship had
  just left.
- **A missing-suite refusal names the conflicting PR** and withholds the reopen that cannot fix it. Any PR
  left open across a large merge can reach this.
- **A stale-CI fetch keeps git's own diagnosis** instead of replacing it, which is the difference between a
  diagnosable failure and a retry in the dark.

**No action needed on any of them.** They arrive with the update.

### A new option: pack your test shards by measured duration

If your sharded test gate is slow, you can now hand it a `suite-durations.json` beside your suites and it
will pack and order its shards from those figures instead of striding over a filename sort. On the source
repo's 65-suite pool that is **305s to 237s**, with no test, assert or scenario touched.

**It is inert until you opt in.** With no durations file the gate strides exactly as before -- same files,
same order, same coverage. A listed suite that no longer exists is ignored; an untimed suite is charged the
maximum so it opens in the first lanes; a missing, unparseable or empty file falls back to the stride.
Stale data can cost wall clock, never coverage.

Two things worth knowing before you generate one. Use **your CI's own durations**, not a workstation's --
these suites run 3.6 to 4.0x faster on a workstation and the ratio is not uniform, so packing CI from
workstation figures lands worse than no data at all. And **both halves are needed**: a balanced shard whose
heaviest file is dequeued last still ends on that file's tail, so packing without longest-first ordering
measured *worse than doing nothing*.

The gate's docstring now carries the arithmetic for when adding another shard stops paying -- the bound is
`max(longest file, lane-seconds / lanes)`, and the old text answered that question in the wrong direction.

### Smaller repairs that need nothing from you

- **The Shopify CLI is never invoked bare.** A pull that fails now cleans up its mirror and says so; a
  preview push that fails says `Push failed.` instead of ending on a `NativeCommandError` naming a file
  inside `AppData\Roaming\npm`. Nothing changes on a successful run. This matters now because the
  environment changed, not the code: the CLI writes a `claude-code-hint` line to stderr *while succeeding*
  when it runs under Claude Code.
- **The Asana mirror can no longer drop a pending close or reopen** during a triage burst. The old failure
  left no red run and no failed check -- just a `cancelled` run nobody investigates and a card in the wrong
  column, which the daily sweep never covered because it only moves cards forward.
- **The fold places an entry by its landing stamp**, not always at the top. Your own held folds were
  misplacing entries too; nothing errored, and the wrong order surfaced only in a published release
  document. A fold script one release behind keeps working -- the new parameter's absence is the old
  behaviour.
- **The PR placeholder list is append-only again.** If you adopted a release between August 27 and
  September 3, the affected string is checked into your own `.github/pull_request_template.md` where an
  update does not rewrite it. No migration: the string is recognised again on the next update.
- **`prune-merged -IncludeRemote` names what it measured** instead of asserting a recycled name that may
  not exist.
- **A bounded `git push`/`git fetch` that stalls and is force-killed** now still gives you the timeout
  diagnosis rather than an unrelated `IOException`.
- **Your advisory CI can explain its own red mark** in `ship-pr`'s console by emitting one
  `::error title=...::...` line. Before, the reason was reachable only by opening the run.
- **The lint gate prints its own wall-clock**, symmetric with the test-gate timing you already see.
  Console output only.
- **A split git/gh identity is reported at session start** instead of being discovered from a tracker that
  disagrees with its own branches. If you run one account you will never see the line.
- **`actions/checkout@v4` is now `@v5`** across the shared workflow templates, so the deprecation line
  drops out of your Actions log.

### Documentation that was telling you the wrong thing

Nothing you run changes in any of these; what changes is that the page you reason from matches the code.

- **The regex dialect for `Get-ShopifySyncReferencePattern` is .NET, not git BRE.** The seam table said
  `--grep`. This is the one worth re-reading if you have already answered it: a pattern that works in one
  dialect and not the other does not fail loudly -- it fails as a floor that is silently too recent, so the
  exclusion rule protects fewer files and the run still reports a reference point and goes green.
- **The heading levels in the portable pages** now match what your own scaffolder writes. Four skill pages
  and three portable pages told you to write `##` where the scaffolder writes `###`, and the shipped PR
  template told you to paste from a `## DEPLOY:` line your document has not carried since August 26. The
  corrected form is *appended* to the tolerance list rather than replacing the old one, so a template you
  have not migrated keeps getting a description.
- **Six pages still taught the retired fixed-filename argument** for the branch document, including
  `skills/new-branch/SKILL.md` -- which lands in context at the exact moment a session is about to create a
  branch. You now get the reversal, dated, with a link to the measurement behind it.
- **The pre-task sync's scope is stated once**, in the skill both other pages point at. You stop running a
  live theme pull, a full-theme comparison and a possible hard refusal at the start of documentation,
  tooling, CI and config work that cannot touch a theme file -- and stop having one unmerged sync PR block
  the start of it.
- **Sandra's manual teaches the content rule**, not the time window it replaced. Until now it would have
  taught you to predict the wrong verdicts, most sharply where the two rules disagree and the retired one
  reverts merged work.
- **The ticket-work section names what a host tracker already owns**, before you reach the first rule --
  which fields you are about to write down twice, and which one only looks like a duplicate. Measured in
  the originating repo: after eleven ticket files were moved verbatim into its tracker, 12 of 12 carried
  their title twice.
- **Taking a request in is a visible state change**, with the two questions that raises answered: which
  column, and which board when the request lives on more than one. The cost of skipping it lands on the
  requester, who cannot see your repo and reads the un-advanced row as "not picked up".
- **Step 5 names the workspace the prio field cannot cross**, so a provisional `ASANA_PROJECT_GID` tells you
  what it costs from the page rather than from watching a daily run label only half your board.
- **The standing-predecessor guard proves the ref was merged**, not just its name. A run that missed a
  predecessor looked exactly like a run that had none: measured in a consumer on 2026-09-01, `4.27.0`
  reported `1 found on origin, all merged` while that branch had an open PR.

## What it is worth

**Parallel work was quietly broken, and this release is where it stops being broken.** The branch document
sat at one fixed path, so every merge to the trunk left every other open pull request conflicting on it --
and a conflicting PR gets no check suite at all, which means it cannot go green and cannot merge. The cost
was not a visible failure but a throughput ceiling nobody could point at: the more work in flight, the more
of it stalled, with no red check to diagnose. Naming the document after its branch removes the ceiling
outright, and it removes it without a migration, which is the difference between a fix and a project.

**The ship path stopped spending its failures at the most expensive moment.** Six guards that used to fire
*after* the entry gates, the suites and the push now fire in seconds, before it -- and the two that cannot
move now say what happened instead of sending an operator into their own code for a state no branch can
repair. The label check is the clearest case: a repo setting somebody else changed org-wide, previously
discovered at the end of a full gate run and leaving a state indistinguishable from a parked branch, now one
API call at the start. Each of these is a wasted CI window and an operator hour that no longer gets spent.

**The required check every pull request waits on got 22% shorter, for free.** 305s to 237s on the measured
pool, with no test, assert or scenario touched -- and the mechanism is a hint rather than a contract, so
stale data can cost wall clock but never coverage. The same work retired a much larger proposal on the
strength of its own arithmetic: splitting the heaviest test file would have bought roughly fifteen seconds
for the price of preserving 340 asserts across ~2,950 lines. Knowing which optimisations *not* to buy is
worth as much as the seconds.

**The work-tracker mirror closes a gap that cost a colleague's trust rather than a developer's time.** A
request filed while the board still read `New` looked untouched to the person waiting on it, so they chased
it in the one place with no answer. The board's sections now move as the work does, the priority the
business set reaches the issue list, and a triage burst can no longer drop a close or a reopen without
trace. That last failure was the expensive kind: no red run, no failed check, just a cancelled run nobody
investigates and a card in the wrong column.

**Two silent-wrong-answer classes are closed at the mechanism.** A live-theme sync that could not reach
origin used to continue and report `none on origin` -- indistinguishable from having asked and found
nothing -- and a network call with no bound could hang fifteen minutes on a credential prompt nothing was
listening to, in the one script whose in-flight copy of a third party's theme edits lives only on a local
branch until the push lands. Both now refuse. A wrong answer is expensive precisely because it is believed.

**What this release cost:** **19m 30s** end-to-end, from the first state check at 08:53:18 to the last
attachment landing at 09:12:48. Six legs, every one of which blocked a person:

| leg | |
|---|---|
| opening state check, and reading the 97 pending entries | 2m 12s |
| the cut itself -- lint, suites, and every generated document | 4m 28s |
| reading the assembled artifacts before making them public, plus both pushes | 1m 29s |
| tracing and filing the one defect the artifacts revealed, and writing this document | 5m 31s |
| the gates again, before the release-notes commit | 5m 23s |
| that commit, the publish, and both attachments | 27s |

**The gates are 46% of the release** -- 247s at the cut and 289s before the notes commit, 8m 56s of the
19m 30s, the same 65 suites run twice by design: once by the cut and once from the trunk before the commit
that follows it. That is the cost the two-commit shape buys, and it is the only leg worth attacking. The
publish itself is 27s and the writing is not compressible by tooling.

Worth recording for the next cut: **the second gate run was 42s slower than the first** on an unchanged
suite set (289s against 247s), on the same machine within twenty minutes. Neither figure is wrong; a
sharded gate's wall-clock moves with lane scheduling, which is the reason the packing work above orders
by recorded duration rather than trusting any single run.

## What was still open at this release

The `bwj-codex` rename needed a one-line settings change in each adopting repo, which lands in those
repos rather than here.

Both BWJ store repos still pointed `Get-AsanaProjectGid` at the same provisional "Test" project, in a
different workspace from the board -- so the stages and the priority label could not both work until each
repo repointed it. `smartwatchbanden#470` and `xoxowildhearts#194` each carried their own half.

One entry in this release, `docs/language-layers-bypass-restored-v1`, carried a doubled
`#### Pull Request` section, so its line in the generated GitHub Release body arrived without a
hyperlink -- 96 links across 97 bullets. The cause was traced to the branch document gaining a second
section between park and merge rather than having its existing one filled in;
[#1367](https://github.com/DKJ-Solutions/claude-code-specialists/issues/1367) carries the measurement.
It was not repaired in this release, which was already committed and tagged when it surfaced.
