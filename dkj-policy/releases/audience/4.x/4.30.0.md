# Release notes v4.30.0 🚀

**Date:** 2026-09-05\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

The workflow plugin is now dkj-policy, and consumers re-install under the new ids

## What changed

### You must re-install the workflow plugin under its new id

`contributing-davekjohn@` and `bwj-codex@` no longer exist. They are now **`dkj-policy@`** and
**`dkj-policy-bwj@`**, and a `.claude/settings.json` still naming an old id resolves to nothing --
**silently**. There is no error: the session simply starts without the plugin, no workflow skills
appear in your slash list, and no session-start check prints.

Do this once, in each repo that enables the plugin:

```powershell
claude plugin uninstall contributing-davekjohn@claude-code-specialists --scope project
claude plugin marketplace update claude-code-specialists
claude plugin install dkj-policy@claude-code-specialists --scope project
# BWJ store repos only, for the companion plugin:
claude plugin uninstall bwj-codex@claude-code-specialists --scope project
claude plugin install dkj-policy-bwj@claude-code-specialists --scope project
```

Then restart the session. `INSTALL.md` carries the same procedure as its own section.

**Renaming your `contributing-davekjohn/` folder to `dkj-policy/` is optional and nothing breaks if
you leave it.** One half-way state to avoid: re-running `adopt-workflow-folder` before you rename
writes a *second* folder beside the one holding your changelog and release history. If you do
rename, `git mv` it -- and if your `repo-config.ps1` states `Get-ChangelogPath` or a release-note
root by hand, repoint that answer in the same commit. A repo on the computed default is carried
across for free.

**One thing you lose until you migrate:** the connector check resolves each registered plugin id
against the marketplace, reports an id the marketplace no longer declares as `[INFO]`, and skips
that plugin's block. So your workflow plugin will not be reported as version-drifted until your
registration catches up.

### Working one repo from two machines no longer strands you

If you fold a changelog entry on one device and then push from another, the fold used to leave a
correct-looking commit on the trunk that no documented route could resolve. The push is now
refused with the answer you need: whether the work is already upstream and your local commit is
redundant, or whether it is real work to integrate. **No action needed** -- you get this the next
time it happens.

The same handoff is guarded one step earlier: `new-branch` now warns at checkout, rather than at
the push, when the branch you are resuming is behind its own remote head.

### Your session start is faster, with one hook where there were two

The two consumer-prose checks are now a single check walking the corpus once: **~457 ms back per
session**, and one hook instead of two. Nothing to migrate -- the merged names never shipped -- and
the report is unchanged: one block per defect actually present, and a run never stops at the first
one it finds.

### A new check tells you when a shared convention moved under your documentation

Until now, nothing could. A sentence in your own docs restating a plugin rule is correct the day
you write it and becomes wrong the day the plugin's answer changes -- and noticing required someone
reading a repo the source never reads. The retired-name check runs at session start (365 ms, never
blocking) and says so. `CONTRIBUTING-portable.md` gains the paragraph explaining what it means when
it fires and what the repair is.

### You can now check your own `CLAUDE.md` against the plugin's policy

A new opt-in skill reports where your repo's constitution has started restating rules the plugin
owns. It is **report-only** -- the repair stays an ordinary branch + PR in your repo. A consumer
that never invokes it sees no change.

### `-SkipStaleBase`: new-branch refuses a stale base

`new-branch` now refuses to branch from a base that is behind, with `-SkipStaleBase` as the valve if
you mean it. **Action only if you branch from a deliberately stale base** -- pass the flag.

### For the two BWJ store repos

- `bwj-codex/SYNC-LOG.md` is scaffolded at `adopt-bwj-asana` time, so it is ready for your first
  sync branch instead of arriving with it. A repo that already has the file sees no change.
- Third-party live-theme drift is recorded in the tree and greppable, where it previously lived only
  in a PR body nobody re-reads. Costs you one line in `scripts/repo-config.ps1`.
- The `Github Issue` and type custom-field conventions for the Asana board are documented, with an
  optional seam that fills them at task creation. **Defaults to off** -- a board without those
  fields sets nothing and sees no change.
- Troubleshooting a self-filed ticket that never gains a prio label: the test is now *is the field
  added to this project?*, not a workspace-level check.

### Documentation corrections you may have been reading around

- `README.md` no longer claims an install record cannot say *installed, project scope, correct sha*
  while the session is inert. It can. Verify the session instead: is the bootstrap skill in your
  slash list, did the session hooks print, does the orchestrator open the turn?
- The cut-release checklist no longer states cut-then-push as a rule for a live stage. It is a
  default, and the page names the property of your target that decides the order -- a push that can
  fail or be partial pushes first, so you do not publish a release describing a state no customer
  saw.
- The prose half of the layering corollary is **unenforced by design**. Stop waiting for that gate.
- The close-out receipt has a stated length bound and a stated order between its two rules, where it
  had *"a handful"*.

## What it is worth

**The names now state the order, which was the point.** `contributing-davekjohn` said what the
plugin was *called after*; `dkj-policy` says what it *is* -- the page that outranks a consumer's
root `CLAUDE.md` on every subject it addresses. `dkj-policy-bwj` says the same for the one ministry
under it. Nothing about the precedence rule changed, no plugin gained or lost a skill, and the
migration is four commands typed once per repo. That is a cheap moment to spend on a name that
stops having to be explained.

**One class of incident is closed rather than mitigated.** A maintainer working a repo from two
machines could reach a state the constitution forbade every route out of -- the tooling produced a
correct-looking commit on the trunk and then left them unable to resolve it without help. On the day
it was measured, five hand-typed commands were needed and the resolution did not get made at all.
That is now answered at the moment of refusal, without a developer.

**Drift between a consumer's own documentation and the plugin's rules stopped being invisible.**
Two mechanisms shipped for it this release -- a session check that fires when a convention moves,
and an on-demand skill that reads a repo's constitution against plugin policy. Both are
report-only. The value is not the automation; it is that the failure now has a witness. It
previously required someone to read a repo the source never reads, which is to say it required
luck.

**And session cost went down while checks went up.** Two prose checks became one hook walking the
corpus once (~457 ms per session returned), and the new retired-name check costs 365 ms -- so the
net session-start budget is roughly flat despite gaining a capability.

## What was still open at this release

**Consumer migration had not happened.** At the moment of this cut, every consuming repo still
enabled the old plugin ids, and `connectors/` still registered them. Until each repo migrates and
the register catches up, the workflow plugin cannot be reported as version-drifted there -- an
accepted `[INFO]`, deliberately not an error, because making it an error re-opens four known false
alarms. The next step sat with whoever maintains each consuming repo.

**The folder rename was left to each repo.** `contributing-davekjohn/` to `dkj-policy/` is optional
and no repo had done it at this release.

**The prose half of the layering corollary was left unenforced on purpose.** A check for it was
measured and declined; the ranking itself is what makes a divergence nameable. No further work was
planned.
