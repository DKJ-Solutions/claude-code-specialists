# Release notes v4.32.0 🚀

**Date:** 2026-09-07\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

Retire the merge queue as policy for detect-and-rebase, repair ship-pr's required-check handling, and fix the Asana mirror and BWJ connector registers after the org move

## What changed

Most of this release arrives on the update with nothing for you to do. Two items need a hand, and
only in the narrow case named on each -- they are first, in the order to do them. Everything under
[Nothing to do](#nothing-to-do-these-arrive-on-the-update) needs no action at all.

### 1. Re-check which Asana board your BWJ store points at -- **act only if you adopted `adopt-dkj-policy-bwj` under the old wording**

The adoption page used to tell both BWJ stores to share one Asana board. It does not any more: each
store repo answers `Get-AsanaProjectGid` with a board of its own, and the value is never copied
between them. A shared board fails silently -- the create call succeeds, fields write, sections still
move a card -- and the only symptom is colleagues on one store finding the other store's tickets on
theirs. If you adopted before this release, open your `scripts/repo-config.ps1` and confirm the GID
names *your* store's board.

Same page, no behaviour change: `Github Type` is documented as the multi-select it always was, and
`adopt-dkj-policy-bwj` now refuses to run in a checkout that is not one of the two BWJ store repos.

### 2. Move your translated changelog tally to the new keys -- **act only if you translated it**

If your `Get-ChangelogPendingSummaryOverrides` answers `Lead`, `Bucket` or `AudienceShare`, those
three keys are retired. An answer for a retired key is not an error -- it is silently ignored, and
the tally line comes back in English. Replace them with `Share` and `NoShare`, and note that the
bump word is seamed too now (`Minor` / `Patch`), with reorderable placeholders. A repo that
translated nothing is unaffected.

### Nothing to do: these arrive on the update

- **The Asana mirror's reconciliation sweep runs again.** If you run `dkj-policy-bwj`'s mirror, its
  daily sweep had been crashing on the first close comment it needed to write -- and taking the
  prio-label and stage sweeps down with it -- while every run stayed green. Cards stopped moving and
  closed tickets stopped being commented on, silently. Updating restores all three sweeps; nothing
  needs re-configuring. A new test suite holds every shipped template to the property that broke,
  so this class cannot come back unnoticed.
- **`ship-pr` waits for a slow required check instead of merging past it.** It had been declaring
  CI green off the first fast check to pass, even when that check was not one your ruleset requires
  -- then walking into a blocked merge and leaving the PR open with a green tick, the merge and the
  fold owed to a session that then exits. On any repo whose required check outlasts a fast advisory
  one, that fired on every ship. Fixed; no change in use.
- **A merge queue is no longer this workflow's policy.** GitHub only offers one on a private repo
  under Enterprise Cloud, or on a public org-owned repo -- so the old policy prescribed a setting
  most consumers cannot switch on. Detect-and-rebase is the mechanism now, and it runs anywhere:
  `ship-pr` dates its run behind your required check, counts what the trunk gained after it, and
  refuses the merge when that is not zero, naming the commits. Where you *do* run a queue, nothing
  is taken away -- `adopt-dkj-policy` Part 3 (`adopt-merge-queue.ps1`) still builds the floor and
  still refuses to pull the switch for you, and both CI runners still catch what a queue merge
  skips.
- **`CHANGELOG.md` now says how much is waiting for the next release.** One machine-written line
  under `## [Unreleased]`: how many entries are pending, how many reach your audience, and which
  bump that work has earned. The fold rewrites it after every merge; the cut clears it. Every word
  is overridable through `Get-ChangelogPendingSummaryOverrides` (see item 2), and a trailing HTML
  comment marks the line as machine-written so a note of your own in that space is left alone.
- **`fold-on-merge.yml` corrections**, for repos that adopted the merge-queue floor: the merge
  stamp is rendered in UTC so a changelog folded from both CI and a laptop no longer orders itself
  by the maintainer's timezone; the fold runner checks out the trunk tip; the concurrency group is
  constant per trunk; and the red-run triage note names the token-checkout failure mode first.
- **Workshop bookkeeping caught up with the BWJ org move.** `connectors/smartwatchbanden.json`
  points at the live `BWJ-Development` repo again (the `BWJ-ecommerce` original is archived, with no
  redirect), and `dkj-policy-bwj` states its scope by *store* rather than by org, so a precondition
  check that had started failing on the moved repo passes again. Invisible to anyone outside this
  repo's maintainers.

## What it is worth

**Two silent failures were the reason to cut this release, and both had every run reporting green.**
The Asana mirror's daily reconciliation sweep -- the mechanism that moves cards on a project-status
change, since that fires no webhook -- had been unable to complete since a helper was renamed, and
nothing said so. `ship-pr` had been calling CI green off a check the ruleset did not require, then
leaving finished work past every gate and past the PR with the merge and the fold unowned; a later
session would find an open PR with a green tick and no visible reason it never landed. Neither cost
anything loudly. That is the class this release closes, and in both cases the fix also closes the
*class*: a new suite holds every shipped template to the property the mirror broke, and the green
path in `ship-pr` now consults the same required-check verdict the refusal path already did.

**The merge-queue retirement removes a prescription most repos could not follow.** The workflow had
made a merge queue its policy for every consuming repo, and a merge queue is a setting GitHub hides
on the plans most of those repos are on. Detect-and-rebase replaces it and runs everywhere, so a
consumer's correct state stops being reported to them as a gap.

**And the changelog now answers "how much is waiting" without anyone counting entries by hand** --
a small thing per release, paid at every one.

## What was still open at this release

- **Each consuming repo migrates itself.** Nothing in this release can move a retired override key in
  somebody else's `repo-config.ps1`, or re-point an Asana GID that a shared-board adoption left
  wrong. The two items at the top of *What changed* are the consumer's to run.
- **The BWJ org move is not finished.** `smartwatchbanden` is in `BWJ-Development`; `xoxowildhearts`
  still lives in `BWJ-ecommerce` while `BWJ-Development/xoxowildhearts` already exists. The register
  and the BWJ skills match by repo **name** now, which is the half that does not move, so neither
  outcome of the remaining move breaks them.
- **This repo's own `origin` remote still spells the old owner.** The release push reached GitHub
  through the account-level transfer redirect from `DaveKJohn/` to `DKJ-Solutions/`. The redirect
  holds only while nothing is created at the old path; the canonical name is
  `DKJ-Solutions/claude-code-specialists`. Filed for this repo, not a consumer concern.
