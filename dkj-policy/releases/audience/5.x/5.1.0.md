# Release notes v5.1.0 🚀

**Date:** 2026-09-12\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

Adoption gaps close - shared BWJ mechanism, one-command plugin updates, and a portable reach label

## What changed

This release is mostly the **aftermath of the v5.0.0 rename**. The two procedures a consumer of this
marketplace actually follows -- installing and uninstalling -- each turned out to carry a step that was
wrong or silent after the flag day, and those repairs lead this page because they are the ones that can
still cost you something. Everything below them is new capability you can take or leave.

### Act now if this is you

**Your issue filing stopped working after you renamed your reach label.** If you renamed `tier-1` to
something else, `report-issue` has been failing outright -- `gh issue create` errors on a label your repo
does not have, so the issue is never filed. Answer `Get-ReachLabel` in your own `scripts/repo-config.ps1`
with the name you actually use, and it works again. Running `adopt-dkj-policy-bwj` will no longer
re-create `tier-1` beside the label your issues are really on.
([#1845](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1845))

**If you are uninstalling on a machine with more than one checkout, stop at Step 4 and skip Step 5.**
`UNINSTALL.md` told you to run `claude plugin marketplace remove`, which is machine-wide over install
records -- so tearing down one checkout by the book silently removed this family's install records from
*every other repo on that machine*. You would see no error: `enabledPlugins` still reads correct, and the
hooks that would have complained left with the plugin. The page now says so, tells you what skipping
costs, and gives you the query that answers *"am I the last checkout?"*
([#1828](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1828))

**If you are still migrating checkouts to the new marketplace name, the pages no longer send you into a
dead end.** `marketplace remove` ends the migration for your *other* checkouts too, and `INSTALL.md` now
says each migration section must reinstall what that command dropped. A second checkout used to hit a red
error at a step the page's own Step 3 had already made impossible -- nothing was broken on your machine,
the CLI's wording just said otherwise.
([#1825](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1825),
[#1827](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1827))

**Check that you registered the marketplace under its current name.** The connector register and the
install page still named the retired one. Registering the wrong source succeeds, installs fine, and looks
correct -- until the day the redirect stops answering, at which point it fails for whoever followed the
instructions exactly. Re-register on `DKJ-Solutions/dkj-claude-plugins` if you are on the old spelling.
([#1822](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1822))

### A short migration, when it suits you

**The reach label is now `minor`, and one command gives you the worklist.** This is the first issue label
this workflow has ever prescribed -- your other labels remain entirely your tracker's business.
`gh label create minor` (or `adopt-dkj-policy` Part 4, which now does it for you) buys you
`is:open label:minor`: every open issue whose landing will be visible past your own developers. If you
already run the axis under another name, either rename the label -- GitHub keeps every issue on it -- or
answer `Get-ReachLabel`. No action needed if you do not want the worklist.
([#1872](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1872))

**BWJ stores: your priority labels unify on `prio-1`..`prio-4`.** Two `gh label edit` commands per store,
documented in the skill. Nothing breaks before you run them.
([#1849](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1849))

**On Windows, the README block top-up tells you the truth again.** It reported "drifted" on every single
run, so a block that really was stale looked exactly like one that was current, and the only way to tell
them apart was to run `-Apply` and read `git diff` afterwards. That is the feature v5.0.0 announced as
*"can be kept current with one command"*, and it now is one.
([#1834](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1834))

### New, and nothing is required of you

**Hand a preview over as one link instead of a wall of URLs.** For BWJ stores, `push-preview` now
produces a published page with one card per market: a QR code to the preview, the preview and
live-control pair beneath it, and what a URL cannot say -- how to see the change, what the gates already
proved, and the one question being asked. The measured handover it replaces was ten 70-to-100 character
URLs in a terminal table that wrapped until the *which market, which page* columns were gone, could not
be selected to copy, and was being read on the phone the change only existed on. Every other Shopify
consumer gets the generic half -- a closing note whenever more than one URL is printed -- and a
single-market repo sees no new output at all.
([#1882](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1882),
[#1877](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1877))

**BWJ stores stop maintaining the same mechanism twice.** `dkj-policy-bwj` now owns the shared floor,
including the storefront and preview URL builder both stores had written separately under different
filenames -- which is why no search in either repo would ever have found the other. Adoption is one
forwarder plus a seam answer, no suite changes, and the README says how. One store gains three
capabilities it never had, including the preview parameters whose absence had already cost a whole review
to reading live while believing it was the preview.
([#1887](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1887),
[#1894](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1894))

**When you pick up an issue, you are told if somebody already pushed a fix for it.** `claim-issue` now
names who parked a commit and how long ago -- at the one moment duplicate work can still be prevented for
free, rather than at the gate that would eventually have noticed.
([#1883](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1883))

**A machine that cannot commit is caught before a branch is cut,** instead of failing at exit 128 once
`HEAD` has already moved. The reading is `git var GIT_AUTHOR_IDENT` rather than `user.name`, which
disagreed with git in both directions. Relatedly, the session check stops reporting a clean "identity is
fine" on a machine that has none.
([#1871](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1871),
[#1835](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1835))

**Update every plugin in a checkout with one command.** `update-plugins` refreshes the marketplace clone
once, updates each plugin the checkout enables, then prints `plugin-versions`' own receipt -- so you read
the result off the tool that would have reported you as behind, rather than trusting the update commands'
say-so. `-DryRun` shows every command without running any.
([#1893](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1893))

**Two smaller things.** Adoption now places the PR template into your `.github`
([#1859](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1859)), and if your checkout was cloned
before a rename or an org move, the connector check stops telling you five plugins are not enabled and
tells you the one true thing instead -- the folder it is reading is not the repository the register names
([#1826](https://github.com/DKJ-Solutions/dkj-claude-plugins/pull/1826)).

**After updating, refresh the marketplace clone first:**
`claude plugin marketplace update dkj-claude-plugins`, then update the plugins. A stale clone reports
success with a plausible version number and no version in the output, so you cannot tell from the result
that you got the previous release.

## What it is worth

**The expensive half of this release is risk that was invisible.** Four of the five leading items above
are failures a consumer could not have detected from their own side: an uninstall that removes other
repos' records while every visible signal still reads correct, a registration on a retired name that
works perfectly until the day it does not, a drift verdict that says the same word whatever the truth is,
and a migration page that produces a red error at a step it had already made unreachable. None of them
announces itself. The cost of each is not the minutes to repair it but the moment of discovery being
chosen by us rather than by the person it lands on -- which is the whole argument for naming them in a
document like this one rather than letting a release carry them silently.

**One colleague was blocked and is not any more.** `report-issue` had been failing outright in a store
repo since September 11, for the single reason that the label name was written as a literal; every
finding a session tried to file there was simply lost. That is the clearest time saved in this release,
and the seam that fixes it means the next repo to rename a label costs nobody anything.

**Two stores stop paying twice.** The BWJ floor convergence and the shared URL builder remove a standing
duplication where the same capability existed under two filenames in two repos -- so a repair in one had
no route to the other, and one store had been missing three capabilities for weeks without anything
reporting it. Adoption is deliberately one forwarder, so neither store has to stop what it is doing to
take it.

**And the routine cost of running this workflow drops slightly.** Updating a checkout's plugins goes from
1 + N commands to one; picking up an issue tells you whether somebody already fixed it; a machine with no
git identity is caught before it costs a branch. Individually small, all of them things a developer
previously had to remember.

**What it cost to produce:** the cut's gates ran 99 test suites in 312s at four lanes -- deliberately four
and not the default thirty, since a gate that dies halfway leaves a half-cut release on the trunk. Clock
started 12:03:26; the release commit and tag were pushed at 12:10:48, a subtotal of **7m 22s**. The
end-to-end total is below.

## What was still open at this release

**This repo's own installed copy was a version behind at the moment of the cut.** It consumes the plugins
it ships, so the marketplace clone and all six plugin installs still had to be refreshed before any hook
or agent def added by this release loaded here. That is the ordinary state after every cut, not a defect.

**The tier-2 question was read two different ways inside this release.** Two entries about issue labels in
the same two store repos scored `N/A` and `4` on the same audience question -- one reading "tier 2" as the
store's end customer, the other as the store repo itself. The prio-label migration above is on this page
because of that disagreement rather than because its entry asked to be; the inconsistency was filed as
[#1896](https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/1896) rather than resolved here.

**The marketplace was not published to the business organisation as part of this release.** Recording a
version and changing what colleagues receive are separate decisions, and only the first was asked for.
